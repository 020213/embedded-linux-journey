## 一、三个函数的实现要点

| 函数 | 是否允许重叠 | 实现 |
|---|---|---|
| `my_memcpy` | ❌ 不允许（重叠即 UB） | 一律前向：`while (n--) *d++ = *s++;` |
| `my_memmove` | ✅ 允许 | 只判 `d < s`：真则前向，否则后向 `d += n; s += n; while (n--) *--d = *--s;` |
| `my_memset` | — | 按字节写，`c` 转 `unsigned char` 只取低 8 位：`while (n--) *p++ = (unsigned char)c;` |

三个函数内部指针一律用 `unsigned char *`，不用 `char *`，不用 `void *` 做算术。

=== P4 memset 返回值 / n=0 / 填充字符 ===

**读法三条**

1. `17352 轮` 的口径偏宽：脚本判的是 `d_off != s_off && n > 0`，不保证两区间真的相交。真重叠应判 `d_off < s_off + n && s_off < d_off + n`。数字虚高，但**结论不受影响**——只要 `d_off != s_off`，memmove 都必须与 libc 逐字节一致。
2. `my_memcpy` 的 20000 轮是**非重叠**场景，本来就该全对（`d<s`、`d>s` 都走前向都正确）。这 20000 轮的作用是拦手误（边界少一次、指针加减错位），不能用来证明 memmove 的必要性。memmove 的必要性只有 P2 的 `ABABABABAB` vs `ABABCDEFGH` 能证明。
3. 对拍用的是确定性 LCG（`seed = 20261126u`），可复现。

## 五、六个概念澄清

### 1. 为什么必须是 `unsigned char *`

两条标准保证，只有 `unsigned char` 同时满足：

| 保证 | 含义 | 为什么重要 |
|---|---|---|
| 无填充位 | 一个字节的 8 位全部参与表示数值，没有"空位" | 用 `char *` 时，`char` 是否有符号由实现决定；`unsigned char` 钉死为 0~255 |
| 所有值可表示 | 0x00~0xFF 一一对应 0~255，赋值不发生回绕/符号扩展 | 按字节搬运时逐位保真 |

第三条工程理由：`sizeof(char) == 1` 是标准定义，所以 `unsigned char *` 的 `+1` 严格等于前进一个字节。`int *+1` 前进 4 字节、`void *` 算术非标准，都不能用来做字节级遍历。

实测证据（S1-1-3 P3）：同一段 0x80 字节，用 `unsigned char` 比较得 `97 - 128 = -31`，用 signed `char` 比较得 `97 - (-128) = 225`，符号直接反了。

### 2. `memmove` 为什么只判 `d < s`

判据不是"区间是否相交"，而是"**写入点会不会踩到还没读的源字节**"，这只取决于地址先后。

设 `dst = src + k`：

- `k > 0`（`d > s`）走前向：第 0 步写 `src[k]`，把源的第 k 个字节踩了；到第 k 步要读 `src[k]` 时，读到的已是自己写进去的脏数据 → 全坏（`ABABABABAB`）。
- `k < 0`（`d < s`）走前向：写入点始终比当前读取点低 `|k|` 字节，待读区在更高地址，碰不到 → 安全。
- 后向完全对称：`d > s` 安全，`d < s` 坏。

| 相对位置 | 前向 | 后向 |
|---|---|---|
| `d < s` | ✅ | ❌ |
| `d == s` | ✅（无操作） | ✅（无操作） |
| `d > s` | ❌ | ✅ |

所以 `d < s` 前向、否则后向，两支覆盖全部情况。`d == s` 时两支等价，不用特判。

不相交时走哪个方向都对，所以不必先算 `d + n <= s`——glibc 那条"快速路径"只是性能优化，不是正确性要求。

**加分项**：严格按标准，不同对象之间的指针比较本身是 UB。`d < s` 只在同一数组内有定义。工程写法是转整数比较：

```c
if ((uintptr_t)d < (uintptr_t)s) { /* 前向 */ }
```

### 3. `memset` 为什么只能填 0 和 -1

函数只拿到"地址 + 一个字节值 + 总字节数"，**不知道元素类型、不知道元素大小**。它眼里只有字节，没有元素。

`int arr[N]` 想全填 1，需要每个字节是 `01 00 00 00`（小端），但 `memset` 只能给每字节写同一个值，于是得到 `01 01 01 01`：

```
0x01010101 = 1×2^24 + 1×2^16 + 1×2^8 + 1 = 16777216 + 65536 + 256 + 1 = 16843009
```

只有"每个字节都相同"的值才能安全填充：

| 值 | 内存表示 | 每字节相同 | 能否 memset |
|---|---|---|---|
| `0` | `00 00 00 00` | ✅ | 可以 |
| `-1` | `FF FF FF FF` | ✅ | 可以 |
| `1` | `01 00 00 00` | ❌ | 不行 |

正确写法：`for` 循环逐个赋；结构体清零用 `memset(&cfg, 0, sizeof(cfg))`；动态数组清零用 `calloc`。

### 4. `restrict` 是什么

`restrict` 是给编译器的**契约承诺**："这两个指针指向的对象不会互相覆盖"。

拿到承诺后编译器才能做字长批量搬（x86 `rep movsb`、ARM64 `LDP/STP`）、向量化、指令重排。没有它就只能保守地逐字节处理。

违反契约传重叠指针 → **UB**。UB 不是"结果不确定"，而是"标准不再管，编译器可以据此删调用、重排，崩溃都合法"。当前实现输出 `ABABABABAB` 只是这一版代码在当前优化等级下的偶然表现，换 `-O2` 或换 libc 结果会变。所以不能用它去"验证"memcpy 的行为，只能作为"重叠会坏"的示意。

### 5. `sizeof(p)` vs `sizeof(*p)`

| 表达式 | 含义 | x86-64 值 |
|---|---|---|
| `sizeof(p)` | 指针本身 | 8 |
| `sizeof(*p)` | 指向的对象 | 16（`struct tbox_cfg`） |

真实踩坑：`memset(p, 0, sizeof(p))` 只清了 8 字节，结构体剩下的字段全是垃圾值。必须写 `sizeof(*p)`。

### 6. `while (n-- > 0)` 退出后 `n` 是多少

`n--` 是**先用后减**：最后一次判断用的是旧值 0，`0 > 0` 为假跳出，但自减已经发生，`n` 回绕成 `SIZE_MAX`（64 位下 `18446744073709551615`）。

风险：把这个 `n` 传给下一次操作，等于从 `SIZE_MAX` 开始越界读写，几乎必然 SIGSEGV。

防御：需要保留原值时单独存一份。

```c
size_t original_n = n;
while (n-- > 0) { ... }
```

## 六、八股六问标准答法

**Q1. memcpy 和 memmove 有什么区别？实现上差在哪一行？**
memcpy 要求不重叠（重叠即 UB），memmove 允许重叠。实现上 memmove 多一个方向判断：`d < s` 走前向，否则走后向（`d += n; s += n; while (n--) *--d = *--s;`）。memcpy 砍掉这条路，单一路径更快。

**Q2. 为什么 memcpy 原型声明 restrict？传重叠指针会怎样？**
restrict 是"两个指针不重叠"的契约，编译器据此才能做字长批量搬、向量化、重排。传重叠指针是 UB——不是结果不确定，而是标准不再约束，编译器可以删调用、乱序，崩溃也合法。

**Q3. `memset(arr, 1, sizeof(arr))` 得到什么？正确做法？**
得到每个 int 为 `0x01010101 = 16843009`。因为 memset 只取 `c` 的低 8 位、每字节写同一个值。正确做法：`for` 循环逐个赋 1；或 `calloc` 清零后再循环赋值。

**Q4. memset 清空的密钥缓冲为什么可能被优化器删掉？怎么防？**
数据流分析判定该缓冲区之后再无读取，写入"对程序可见效果为零"，整段调用被当死代码消除，密钥仍残留在内存。防法：用 `volatile unsigned char *` 逐字节写（强制每次写落内存），或用 C11 `memset_s`。

**Q5. sizeof 用在指针和指针解引用上的区别？真实场景？**
`sizeof(p)` 是指针本身大小（x86-64 为 8），`sizeof(*p)` 是所指对象大小。真实场景：`memset(&cfg, 0, sizeof(p))` 只清 8 字节，结构体其余字段是垃圾值，必须写 `sizeof(*p)`。

**Q6. `while (n-- > 0)` 执行完 n 是多少？有什么风险？**
`SIZE_MAX`（64 位下 18446744073709551615）。因为最后一次判断用旧值 0、`0>0` 为假跳出，但自减已发生，无符号回绕成最大值。风险：后续把它当长度复用即灾难性越界。需保留原值时单独存一份。

## 八、S1-1-5 接点（环形缓冲区 v1）

明天开工要直接用到本课的三样东西：

1. **`memcpy` 语义**：环形缓冲区"回绕拷贝"常见实现是 `memcpy(buf + head, src, n1)` + `memcpy(buf, src + n1, n2)`，两段**不重叠**，正是 memcpy 的合法用法；一旦写成 `memmove` 单段搬，就是把不重叠的场景当成重叠处理，多一次方向判断。
2. **`memset` 清零**：`memset(rb, 0, sizeof(*rb))` 清整个结构体是对的（全 0 每字节相同），但**不要**用它给元素数组填非零初值。
3. **`unsigned char *` 视角**：环形缓冲区的 `head`/`tail` 用 `size_t`，取模运算 `(head + 1) % capacity`；一旦出现负索引就是回绕灾难，与本课 `while(n--)` 的 `SIZE_MAX` 是同一类错误。
