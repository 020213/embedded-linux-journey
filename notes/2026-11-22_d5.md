# D5 · 内存四区（进程虚拟地址空间布局）

> 日期：2026-11-22
> 阶段：D5 启动期 / 第 1 块
> 主题：进程虚拟地址空间的五个区域、生命周期、地址判据、设计动机
> 环境：Ubuntu 22.04 (x86-64)，gcc 11，编译加 `-no-pie` 以固定地址段

---

## 0. 一句话结论

> **只读的分开放（能共享、能防写坏）；活得久的静态分配（加载时搞定）；活得短的放栈（零成本回收）；大小不定的放堆（运行时再定）；全是 0 的只记大小（省文件体积）。**

---

## 1. 进程虚拟地址空间全貌

从**高地址到低地址**：

```
高  0x7fffffffffff
    ┌──────────────────────┐
    │        栈 stack       │  ↓ 向低地址增长
    │   局部变量/参数/返回地址 │
    ├──────────────────────┤
    │                      │
    │   未映射空洞（大块）    │  ← 栈堆相向而行，吃穿即崩
    │                      │
    ├──────────────────────┤
    │        堆 heap        │  ↑ 向高地址增长
    │      malloc 来的       │
    ├──────────────────────┤
    │   .bss  （初值0/未初始化）│
    ├──────────────────────┤
    │   .data （非零初值）    │
    ├──────────────────────┤
    │   .rodata（只读数据）   │
    ├──────────────────────┤
    │   .text （机器指令）    │
低  0x0000000000000000
```

### 实测输出（`-no-pie`，真实运行结果）

```c
/* 00_c/1121_mem_layout.c */
#include <stdio.h>
#include <stdlib.h>

int g_init = 42;        /* .data   */
int g_uninit;           /* .bss    */
const int g_const = 7;  /* .rodata */

int main(void)
{
    int local = 1;                    /* 栈       */
    static int s_local;               /* .bss     */
    int *heap = malloc(16);           /* 堆       */
    char *s = "abc";                  /* 指向 .rodata */

    printf("main      %p   .text\n",   (void *)main);
    printf("g_const   %p   .rodata\n", (void *)&g_const);
    printf("s         %p   .rodata\n", (void *)s);
    printf("g_init    %p   .data\n",   (void *)&g_init);
    printf("g_uninit  %p   .bss\n",    (void *)&g_uninit);
    printf("s_local   %p   .bss\n",    (void *)&s_local);
    printf("heap      %p   堆\n",      (void *)heap);
    printf("local     %p   栈\n",      (void *)&local);

    free(heap);
    return 0;
}
```

```bash
gcc -Wall -Werror -no-pie -o build/1121_mem_layout 00_c/1121_mem_layout.c
./build/1121_mem_layout
```

实测输出：

```
main             0x401196       .text
g_const          0x402004       .rodata
s                0x402008       .rodata
g_init           0x404048       .data
g_uninit         0x404050       .bss
s_local          0x404054       .bss
heap             0x3d9923a0     堆
local            0x7ffd9231cd04 栈
```

**从高到低排序**：

```
栈(0x7ffd…) > 堆(0x3d99…) > .bss(0x404054 ) > .data(0x404048) > .rodata(0x402008) > .text(0x401196)
```

注意 `s_local`（`static int`）落在 `0x404054`，与 `g_uninit`（`0x404050`）相差 **4 字节** —— 静态局部变量住在 `.bss`，不在栈上。

## 2. 五个区逐个说明

### 2.1 `.text` — 代码段

| 项 | 内容 |
|---|---|
| 装什么 | **机器指令**（每个函数的编译结果） |
| 权限 | 只读、**可执行** |
| 生命周期 | 程序全程 |

### 2.2 `.rodata` — 只读数据段

名字里 **`ro` = read only**。

| 项 | 内容 |
|---|---|
| 装什么 | 字符串字面量（`"abc"`）、`const` 全局变量、`switch` 跳转表 |
| 权限 | 只读、**不可执行** |
| 生命周期 | 程序全程 |

**`.text` 与 `.rodata` 的区别**：

| | `.text` | `.rodata` |
|---|---|---|
| 内容 | 机器指令 | 数据字节 |
| 能被 CPU 执行 | 能 | **不能**（执行即崩） |
| 能被程序改写 | 不能 | 不能 |
| 举例 | `main` 的地址 | `"abc"` 的地址 |

两者都只读，但一个是"要做的事"，一个是"要用的料"，不能混为一谈。

**易错点：`char *s = "abc";` 是两样东西**

```c
char *s = "abc";
/*  s    → 栈（8 字节的指针变量）        */
/* "abc" → .rodata（4 字节：a b c \0）  */
```

`s` 在栈，`s` **指向的内容**在 `.rodata`。写 `s[0] = 'X'` 会 SIGSEGV，因为改的是 `.rodata`。

### 2.3 `.data` — 有初值的可写数据段

| 项 | 内容 |
|---|---|
| 装什么 | **非零初值**的全局变量、静态变量 |
| 权限 | 可读写 |
| 文件里 | **存实际数据**（每个字节都在可执行文件中） |

### 2.4 `.bss` — 全零占位段

名字来源：**B**lock **S**tarted by **S**ymbol。

| 项 | 内容 |
|---|---|
| 装什么 | **未初始化**或**初值为 0** 的全局变量、静态变量 |
| 权限 | 可读写 |
| 文件里 | **只存大小**，不存数据 |
| 加载时 | 内核给零页（几乎零成本） |

**`.data` 与 `.bss` 的划分判据**：

| 写法 | 段 |
|---|---|
| `int a;` | `.bss` |
| `int b = 0;` | **`.bss`**（显式写 0 与不写等效） |
| `int c = 5;` | `.data` |
| `static int d;` | `.bss` |
| `const int e = 5;` | **`.rodata`**（因为 const） |

**`.bss` 单独存在的意义**：40MB 的未初始化数组，放进 `.data` 会让可执行文件实打实大 40MB；放进 `.bss` 只在文件里记一句"留 40MB，全填 0"，文件体积只增几个字节。

### 2.5 栈

| 项 | 内容 |
|---|---|
| 装什么 | 局部变量、函数参数、返回地址、保存的 `rbp`、临时值 |
| **不装什么** | **函数代码不在栈上，在 `.text`** |
| 增长方向 | **向低地址**（`sub rsp, N` 使 RSP 递减） |
| 回收 | 自动，函数返回时 `mov rsp,rbp; pop rbp` |
| 大小 | 默认 8MB（`ulimit -s` 可查） |

### 2.6 堆

| 项 | 内容 |
|---|---|
| 装什么 | `malloc` / `calloc` / `realloc` 申请来的内存 |
| 增长方向 | **向高地址**（brk 递增） |
| 回收 | **必须手动 `free`** |
| 大小 | 受物理内存与虚拟地址空间限制 |

三个申请函数的区别：

| 函数 | 签名 | 是否清零 | 备注 |
|---|---|---|---|
| `malloc` | `void *malloc(size_t size)` | **不清**，内容是垃圾 | — |
| `calloc` | `void *calloc(size_t nmemb, size_t size)` | **清成全 0** | 申请 `nmemb × size` 字节 |
| `realloc` | `void *realloc(void *p, size_t size)` | 新增部分不清 | **可能搬家，返回新地址** |

**`realloc` 的坑**：失败时返回 `NULL`，但**原指针仍然有效**。

```c
/* 错误：失败时 p 被覆盖成 NULL，原内存地址丢失，再也 free 不掉 */
p = realloc(p, new_size);
if (p == NULL) { /* 此处原内存已泄漏 */ }

/* 正确：用临时变量接，成功后才覆盖 */
int *tmp = realloc(p, new_size);
if (tmp == NULL) {
    free(p);          /* p 仍有效，正常释放 */
    return -ENOMEM;
}
p = tmp;
```

## 3. 生命周期

**生命周期 = 变量从创建到销毁的时间区间**，回答"活多久"，不回答"在哪"。

| 类型 | 存储位置 | 谁回收 | 何时回收 | 初值 |
|---|---|---|---|---|
| 普通局部 `int a;` | 栈 | **自动** | 函数返回时移动栈指针 | 不确定（垃圾值） |
| 静态局部 `static int b;` | `.bss` / `.data` | 系统 | 程序结束 | 0（首次） |
| 全局 `int g;` | `.bss` / `.data` | 系统 | 程序结束 | 0 |
| 堆 `malloc` | 堆 | **必须手动 free** | 调用 `free` 时 | 不确定 |

**核心结论：只有堆需要手动管理。**

### 3.1 `static` 局部变量：作用域 ≠ 生命周期

```c
void f(void)
{
    int a = 0;          /* 普通局部：栈      */
    static int b = 0;   /* 静态局部：.bss    */
    a++;
    b++;
    printf("a=%d b=%d\n", a, b);
}

f(); f(); f();
```

输出：

```
a=1 b=1
a=1 b=2
a=1 b=3     ← a 每次重置，b 持续累加
```

| | 普通局部 `int x;` | 静态局部 `static int x;` |
|---|---|---|
| 存在哪 | 栈 | **`.bss`**（初值 0）/ `.data`（非零初值） |
| 生命周期 | 进出函数 | **程序全程** |
| 作用域 | 函数内 | 函数内（外面仍看不见） |
| 初始化 | 每次进函数重新来 | **只初始化一次，程序启动时** |

**`static` 改的是生命周期，不是作用域。** 两件事必须分开记：

- 作用域回答"**谁能看见我**"
- 生命周期回答"**我活多久**"

### 3.2 栈为什么能"免费"回收

```asm
push rbp          ; 保存旧帧底
mov rbp, rsp
sub rsp, N        ; ← 一条指令划出整个栈帧，所有局部变量一次到位
...
leave             ; mov rsp, rbp; pop rbp  ← 两条指令全部归还
ret
```

栈帧是**一次性划拨、一次性归还**的：没有记账、没有链表、没有查找。这就是局部变量几乎不花性能代价的原因。若局部变量也走堆，每次函数调用都要 `malloc` + `free`，开销会从几条指令变成几百条指令。

### 3.3 栈与堆相向增长

| 区域 | 增长方向 | 撞上的后果 |
|---|---|---|
| 栈 | 向低地址（RSP 递减） | stack overflow / 越界踩到堆 |
| 堆 | 向高地址（brk 递增） | 堆溢出 / 越界踩到栈 |

两者中间是**未映射空洞**，靠相向增长最大化空间利用率；一旦吃穿，表现为 SIGSEGV。

## 4. 地址判据

### 4.1 三条判据

| # | 判据 | 说明 |
|---|---|---|
| 1 | **`0x7ff…` 开头 = 栈** | 无例外（x86-64 Linux） |
| 2 | 其余全在**同一个低地址区间** | `-no-pie` 时在 `0x0040xxxx` 一带；默认 PIE 时在 `0x55…` 一带 |
| 3 | 低地址区间内从低到高：`.text` → `.rodata` → `.data` → `.bss` → 堆 | 由链接脚本决定 |

### 4.2 数量级关系

```
栈  0x7ffd9231cd04
堆  0x000000003d9923a0
差  ≈ 140 TB
```

**栈与堆差 TB 级（10^14 字节量级）**，不是"大一点"。

### 4.3 块内差 vs 块间差

> **同一个区内的地址差 = 数据大小的整数倍；跨区地址差 = 数量级。**

| 情形 | 地址差 | 含义 |
|---|---|---|
| 两个相邻栈 `int` | 4 | 栈内相邻（顺序不保证符合声明顺序） |
| 两个相邻全局 `int` | 4 | `.data`/`.bss` 内相邻 |
| 两次 `malloc(4)` | ≈ `0x20` | 分配器连续块（每块带 header + 16 字节对齐） |
| 栈变量 vs 堆变量 | ≈ 140 TB | **跨区** |

**实用技巧**：拿到任意两个地址，先看最高位。一个 `0x7ff…`、一个 `0x40…`（或 `0x55…`）→ 必然跨区，前者是栈。coredump 里定位野指针时，这比背布局图快。

## 5. 为什么要这么分

### 理由一：只读的挑出来，可共享也可保护

- **共享**：同时跑 10 个相同程序，系统只加载一份 `.text` 到物理内存，10 个进程共用同一份页。这是共享库省内存的根本原因（libc 在几百万个进程里只占一份物理空间）。
- **保护**：野指针误写只读区 → CPU 立刻拦截抛 SIGSEGV。**崩溃比静默改坏数据好**：崩溃能定位，静默改坏可能要几天后才爆且无法溯源。

### 理由二：生命周期对齐，让"免费"成为可能

| 变量 | 存活时间 | 最优位置 | 优势 |
|---|---|---|---|
| 局部 | 进出函数 | 栈 | 移动指针即回收，零成本 |
| 静态/全局 | 程序全程 | `.data`/`.bss` | 加载时一次安排好 |
| 动态申请 | 运行时才知 | 堆 | 编译期无法预留 |

### 理由三：大小编译期未知的只能放堆

配置文件多大、图片多长、CAN 数据包多重——都是运行起来才知道。编译器无法预留空间，只能运行时申请。反之 `int arr[10]` 编译期确定，放栈又快又省管理开销。

### 理由四：全是 0 的只记大小

`.bss` 让 40MB 的未初始化数组在可执行文件里只占几个字节（只记大小），加载时由内核给零页。

## 6. 常见混淆点自查

| # | 混淆点 | 正确认识 |
|---|---|---|
| 1 | 以为 `.rodata` 和 `.text` 是同一块"代码区" | 两个段：一个装指令、一个装数据，都只读但区别在"能不能执行" |
| 2 | 以为 `"abc"` 在栈上 | 指针变量 `s` 在栈，`"abc"` 本身在 `.rodata` |
| 3 | 以为 `.rodata` 装初值非零的静态变量 | 那是 `.data` 的内容；`.rodata` 装只读数据（字面量、`const`） |
| 4 | 以为 `static` 局部在栈上 | 在 `.bss`（初值 0）或 `.data`（非零初值） |
| 5 | 以为 `static` 改变了作用域 | `static` 改的是**生命周期**，作用域仍在函数内 |
| 6 | 以为 `int g = 0;` 在 `.data` | 在 `.bss`（显式写 0 与不写等效） |
| 7 | 以为栈里放"函数" | 栈放参数、返回地址、局部变量；**函数代码在 `.text`** |
| 8 | 以为 `calloc` 和 `malloc` 只差参数个数 | `calloc` **清零**，申请 `nmemb × size` 字节 |
| 9 | 以为 `realloc` 可直接覆盖原指针 | `p = realloc(p, n)` 失败时原地址丢失导致泄漏 |
| 10 | 以为栈地址是 `0xff…` 开头 | 是 `0x7fff…`（`0x7ff` 开头，16 位十六进制） |
| 11 | 以为堆和 `.bss` 挨着 | 相差近 1GB（实测 `0x3d9923a0` vs `0x404054`），都在低半区但不同段 |
