5 本轮问答沉淀（四个概念澄清）
5.1 const char *s 里的 const 管谁
const 贴在 char 左边、* 右边 → 修饰被指的数据，不是指针本身。

写法	意思	哪个可变
const char *p	数据只读	p++ 合法
char *const p	指针只读	p[0]='x' 合法
const char *const p	都只读	都不能
所以 my_strlen 里 p++ 能过编译：动的是指针副本，不是字符串内容。语义是"函数承诺不改你传进来的串"。

5.2 size_t 是什么
长度专用无符号整数，位宽 = 机器地址宽度（32 位 4 字节，64 位 8 字节）。strlen / sizeof / malloc 参数全用它。

坑在无符号：3u - 4u 不是 -1，是 SIZE_MAX = 18446744073709551615。任何两个 size_t 相减再判正负都是错的，C99 之后差值应用 ptrdiff_t。

反过来的理由：返回 int 会在超过 INT_MAX（约 21.5 亿）字节时截断溢出。

5.3 (*d++ = *src++) != '\0' 比的是什么
比较的是赋值表达式的结果——刚写进去的那个字符，不是 *d 也不是 *src（此刻两者相等）。拷到 '\0' 时表达式值为 0，循环停，且 '\0' 本身也写进去了。

同一行语句踩了两个动作：写（越界写）+ 读（取表达式值与 '\0' 比，越界读）——这就是 valgrind 在同一地址报出 Invalid write 与 Invalid read 两笔的原因。

5.4 my_strcmp("ab","abc") = -99 怎么算出来的
'a'=97、'b'=98、'c'=99、'\0'=0。

轮次	*p1	*p2	*p1 != '\0' && *p1 == *p2	动作
0	'a'(97)	'a'(97)	真	双指针后移
1	'b'(98)	'b'(98)	真	双指针后移
2	'\0'(0)	'c'(99)	假（第一子条件不成立）	退出
退出时 p1 指 '\0'、p2 指 'c' → 0 - 99 = -99。

两种退出路径：①字符不等，返回两字符码差；②一方先撞 '\0'，返回 0 - 对方码。所以差值数字会随输入变（"ab" vs "abz" 得 -122），标准只保证符号，判等只能写 == 0。

配套："abc" vs "ab" = 99 - 0 = 99；"" vs "a" = 0 - 97 = -97；"a" vs "" = 97。规律是"谁先到 '\0' 谁小"，即空串排最前，短前缀排前——字典序正确行为。

5.5 valgrind 报告怎么读
三层结构：① 错误条目 Invalid read/write（重点）→ ② HEAP SUMMARY 总账 → ③ 泄漏结论。

单条内部分两半：

前半 = 谁干的：堆栈从下往上读（by = 被谁调用），找最底层带 .c:行号 的
后半 = 这块内存哪来的：Address 0x... is N bytes after/inside a block of size M alloc'd + 那次 malloc 的调用点
措辞	含义	对应 bug
inside a block of size N	块内但已 free	悬空指针（S1-1-2 bug2）
after a block of size N	块外，越过结尾	越界（本课 P5）
本次四条的因果链：

#	条目	位置	偏移	角色
1	Invalid write	my_strcpy:9	0 bytes after	根因
2	Invalid read	my_strcpy:9	同上	同句连带读
3	Invalid read	strlen ← printf:27	同上	求长度时越界
4	Invalid read	mempcpy ← printf:27	4 bytes after	批量拷内容时越界
地址 044 / 046 / 048 差 2、4 字节都在同一越界区间：strlen/strcpy 逐字节走紧贴块尾（offset 4），mempcpy 是向量化批量拷贝、分段推进（offset 6、8）。所以别纠结偏移数字，认 size 4 alloc'd 与 after 两个性质即可。

HEAP SUMMARY 对账：2 allocs, 2 frees, 4,100 bytes = 你的 malloc(4) + glibc 给 stdout 分配的 4096 字节缓冲区（4 + 4096 = 4100）。in use at exit: 0 + All heap blocks were freed = 无泄漏。

核心结论：无泄漏 ≠ 无错误。 两本账都还清（2 allocs, 2 frees），却仍有 4 条越界访问——这就是"能跑通不等于正确"。

7 八股口径自检（§8 六问）
strlen 返回 size_t：无符号 + 位宽等于地址宽度，可表达超过 INT_MAX 的长度；返 int 会截断。
strcpy 返 dest：支持链式，如 printf("%s", strcpy(buf, "CAN"))；标准库"目标在前"函数统一约定。
strcmp 返回值不能判"差几个"：glibc 返回差值（本次实测 -99 / 99 就是证据），换输入就变；== 1 必错，只能 == 0 或 <0/>0。
一句三件事：取字符、指针后移、判终止。不是 UB 因为 d/s 是两个不同指针对象，各自只自增一次（UB 是 *d++ = *d++ 这种同一对象一句改两次）。
车规被禁原因：无长度参数，边界责任全压调用者。替代：strcpy_s（C11 Annex K，glibc 不提供）、strscpy（Linux 内核，T-Box 常见）、自研 my_strcpy_s（越界截断返 -1）。
循环 strcat O(n²)：每次从头扫尾。优化为维护 tail 指针，每次 tail += strlen(tail); tail = strcpy(tail, src);，总 O(n)。
8 交接给 S1-1-4 的三个接点
重叠 UB：本课 my_strcpy 明确要求 src/dest 不重叠（strcpy(buf+4, buf) 是 UB）→ S1-1-4 的 my_memcpy 要处理重叠，答案就是 memmove 的"从后往前拷"。
越界责任在调用者：my_strcpy 不检查边界 → my_memcpy 同样不检查，第三个参数 n 由调用者保证。
size_t n 的参数类型：memcpy/memset 的第三个参数都是 size_t，且 memset 的填充值是 int 但只取低 8 位——新坑。
